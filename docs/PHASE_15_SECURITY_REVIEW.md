## Controls inspected

- `auth_rate_limit_service.py` uses atomic Mongo increments and HMAC bucket identifiers; account reservations precede credential verification. Real indexes, first-upsert races and cross-worker behavior remain untested.
- `auth_service.py` and `session_repository.py` hash refresh/CSRF values, compare-and-set rotation and revoke on replay. `middleware/auth.py` checks session state and CSRF on unsafe authenticated methods.
- Clinical create/update/download routes use role and patient/clinician scope. The reviewed missing/unauthorized object responses are normalized, but the full connected matrix remains pending.
- Quarantine has size/structure checks, private paths, bounded scanner call, clean-only promotion and safe metadata. The new Unix-socket adapter uses byte streaming and fixed reason codes; a fake socket is not an operational scanner.
- `payment_service.py` verifies checkout and webhook signatures and provider payment amount/order before applying captured state, with idempotent persistence paths. Provider behavior, failure/retry and refunds require separate Test Mode review.
- Staging startup now rejects plaintext Mongo transport, conflicting TLS options and certificate verification bypass before database initialization. Synthetic offline tests passed; no staging certificate or network path was contacted.

The complete working tree should receive a final external security review after the operational and connected gates. This review is **FAIL for production release** while the open findings and evidence gaps remain.
