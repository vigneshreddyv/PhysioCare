## Original production defect and focused correction

**Original P1 finding:** `backend/app/core/config.py` called `validate_staging_isolation()` and `validate_development_isolation()` for their environments, but had no production branch at model validation or runtime startup. Defaults included a local Mongo URI, local CORS origins, disabled PDF scanner, and an empty trusted-proxy list. An offline `Settings(_env_file=None, ...)` probe with synthetic JWT secrets accepted `ENVIRONMENT=production`, `MONGODB_URL=mongodb://127.0.0.1:27017/physiocare_dev`, `DATABASE_NAME=physiocare_dev`, disabled payments and scanner, enabled throttling, and no trusted proxies; `validate_runtime_startup()` also accepted it. The probe made **no database connection**. Secure cookie mode alone did not reject this configuration. No deployment using this configuration was identified.

**Root cause and fix:** `backend/app/main.py` already calls `settings.validate_runtime_startup()` before constructing the scanner or initializing the database, and `backend/app/database.py` rechecks it before constructing a Mongo client. The missing production branch in `Settings` meant those calls did not enforce production isolation. The approved local fix adds `validate_production_isolation()` to both settings construction and runtime revalidation in `backend/app/core/config.py`. It also changes `backend/tests/test_development_database_guard.py` and the production cookie contract in `backend/tests/test_api_contract.py`, adds `backend/tests/test_production_configuration.py`, and updates this report. No production hostname, database URI, credential or certificate was chosen or changed.

**New production configuration requirements:** `ENVIRONMENT=production`; explicit `PRODUCTION_DATABASE_HOST` and `PRODUCTION_DATABASE_NAME` matching one credentialed, non-local `MONGODB_URL` target and `DATABASE_NAME`; no development/staging/demo database name; explicit `tls=true` or `ssl=true` with no duplicate, conflicting, unknown TLS/SSL, certificate-bypass or hostname-bypass option. A standard `mongodb://` URI must select an explicit replica set; `mongodb+srv://` is structurally supported. Production also requires throttling, a non-global trusted-proxy network, exact non-local HTTPS CORS origins, an absolute non-symlinked `PRODUCTION_STORAGE_ROOT` with four distinct contained report/quarantine paths, and `PDF_SCANNER_MODE=clamav_unix` with an absolute non-symlinked socket path. Local/demo identity selectors and demo home-visit requests must be disabled. Password, payment, CSRF and role behavior were not changed. Invalid configuration raises a non-secret error before a Mongo client is created.

This is **structural configuration validation**. It does not prove DNS/SRV resolution, certificate chain and hostname matching during a real TLS handshake, Mongo replica-set identity, scanner availability/signature freshness, proxy topology, storage persistence/permissions or backup restoration. Those are separately approved connected and operational gates.
